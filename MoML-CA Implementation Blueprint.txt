MoML-CA Implementation Blueprint
This document outlines a comprehensive 10-week execution plan for MoML-CA (Molecular Modeling &
Machine Learning for Contaminant Analysis), a hybrid framework to model PFAS behavior in water
treatment. The plan is divided into four phases (Foundation, Core Development, Integration & Validation,
Finalization & Delivery), with a detailed day-by-day checklist of tasks. Each task includes technical
instructions (shell commands, code snippets, environment setup) and notes on expected outputs, validation
steps, resource usage, and fallback options. All citations and references are preserved for further reading.

Phase 1: Foundation (Weeks 1–2)
Objective: Establish the development environment, acquire and preprocess datasets, and set the stage for
model development. This phase focuses on data ingestion & processing, tool installation, and initial
prototyping.

Week 2: Model Prototype and Dataset Finalization
• [ ] Day 7: MGNN model design (architecture planning).
• Model Outline: Design the multi-task multi-scale graph neural network (MGNN) architecture 14
15 . Key considerations:
◦ Use a hierarchical GNN to capture both local and global structure 16 . This could be
implemented via graph coarsening or pooling layers (e.g., DiffPool, Graph U-Net, or custom
coarsening as per Cai et al., 2021 17 ). At least two graph resolution levels (fine, coarse) are
intended, enabling information flow in both directions (bi-directional refinement) 18 .
◦ Base GNN layer: likely Graph Convolution (GCN) or Graph Attention (GAT). For example, use
PyTorch Geometric’s GCNConv or GINConv for message passing.
◦ Shared trunk vs. multi-head: Implement a shared feature extractor (several GNN layers) that
outputs a graph-level embedding. Then branch into two heads 19 :
◦ Force-Field Head: Regression output for force-field parameters. One approach is to output a
vector concatenating all parameters for the molecule (as prepared in data loader’s y1 ). Use
MSE loss on this continuous output 20 .
◦ Property Prediction Head: Could output one or multiple properties (e.g., adsorption
potential, toxicity) per molecule (our y2 ). Depending on the nature, use appropriate loss
(MSE for regression, cross-entropy for classification if any categorical property).
◦ Environmental context integration: Since each training example has an environmental feature
vector u , inject this into the model. Options:
◦ Concatenate u to the graph-level embedding before the output layers (simple but effective
for global context).
◦ Or, incorporate u into node features at input (each node gets appended environmental
features) to allow context to influence message passing 13 .
◦ We will go with the simpler approach: after graph convolutions, combine the graph
embedding h_graph with environment vector u (e.g., h_comb = concat(h_graph,
EnvMLP(u)) where EnvMLP is a small MLP to process environmental features). Feed
h_comb into both heads.
◦ Loss function: Define combined loss = loss_ff + λ * loss_prop . loss_ff is MSE over
all force-field parameters (ensuring units are normalized so each term contributes fairly) and
loss_prop is MSE or cross-entropy for properties. We can set λ (weight) to balance training;
initially λ = 1. Use masking for missing labels 8 , e.g., if a molecule lacks a certain property
label, exclude it from that loss calculation (PyTorch: multiply squared error by mask of known
labels).
• Architecture Example (Pseudo-code):

super().__init__()
# Graph convolution layers
self.conv1 = GCNConv(in_channels=feat_dim, out_channels=128)
self.conv2 = GCNConv(128, 128)
# Graph pooling for coarsening (e.g., SAGPool or EdgePool)
self.pool = TopKPooling(128, ratio=0.5)
self.conv_coarse = GCNConv(128, 128)
# Global context processing
self.env_fc = nn.Linear(env_dim, 64)
# Heads
self.ff_head = nn.Linear(128+64, param_output_dim)
self.prop_head = nn.Linear(128+64, property_output_dim)
def forward(self, x, edge_index, edge_attr, batch, env):

h = torch.relu(self.conv2(h, edge_index))
# pool to get coarse representation
h, edge_index_coarse, _, batch_coarse, _ = self.pool(h, edge_index,
None, batch=batch)
h = torch.relu(self.conv_coarse(h, edge_index_coarse))

# incorporate environment

# outputs

# force-field param predictions

(This pseudo-code uses a pooling layer and a global mean pool; actual implementation might differ
depending on library and need to handle batch vs. single graph input.)

• Analyze MGNN Outputs: Use visualization to interpret the MGNN results. For example:

◦ Use a custom output layer for partial charges that enforces charge conservation (e.g.,

• [ ] Day 22: Integration pipeline development – part 1 (MGNN -> MD).
• Integrate MGNN and MD: Write a script pipeline_predict.py that given an input (SMILES +
environment parameters) executes:
1. MGNN Stage: Call predict_forcefield(smiles, env) to get predicted force field
parameters and properties. Also capture the predicted properties output; we might directly
use those as partial results (e.g., predicted adsorption potential, etc., that MGNN gave).
2. Simulation Setup: Using the returned force-field parameters, set up an OpenMM simulation
for the PFAS in water (similar to what we did in Day 13 but for a new input). Possibly we’ll do a
shorter simulation here for integration: the idea is to generate just enough trajectory data to
feed the LSTM (the LSTM needs some initial time-series). Running a full 5 ns for every new
input might be too slow for an interactive tool, so consider a shorter run (e.g., 100 ps or 200
ps = a quick 100k steps). This can still be a bit heavy (a few minutes on GPU), but possibly
acceptable for a single query. Alternatively, we might provide the option to skip MD for speed
and rely purely on MGNN outputs plus some heuristic, but that sacrifices accuracy. We aim for
fidelity, so plan to run a short MD.
▪ Use the MGNN parameters in the simulation as we practiced. Possibly fix heavy atoms
if needed to accelerate (not ideal, we want natural motion, so probably not).
▪ Collect the trajectory from this short run (positions, energies).
3. Feature Extraction: Extract the time-series features from this short trajectory to form
initial_sequence for the LSTM. For example, from 100 ps trajectory, take the potential
energy at each frame and one structural metric (like radius of gyration or end-to-end
distance) at each frame. That gives us sequences of length maybe 50–100 steps (depending
on how finely we sample). This is the input for LSTM.

22

4. LSTM Stage: Call forecast_dynamics(initial_sequence) to predict future evolution.
For instance, LSTM could predict another 400 ps beyond the 100 ps given (if it was trained on
500 ps = 5 ns sequences originally, it might attempt to predict up to that scale).
5. Interpret Results: With the LSTM output sequence, interpret what it means for PFAS
behavior:
▪ Example: if the structural feature (like end-to-end distance) is steadily increasing in the
prediction, that could suggest the molecule is unfolding or perhaps starting to break
apart (if it was to degrade, we'd see some abnormal trend).
▪ If potential energy is dropping and plateauing, maybe it indicates the system reaching
a stable state or possibly being adsorbed.
▪ We might not have direct "degradation products," but we can infer trends like “the
PFAS is likely stable vs. likely to change conformation significantly.” We may also
combine MGNN’s property predictions here: e.g., MGNN might have predicted a high
“adsorption potential” property for this PFAS, meaning it likely sticks to surfaces. If
that’s high and the LSTM shows energy dropping (which might indicate binding), we
can infer it would adsorb in a filter.
▪ For the sake of delivering something actionable: If MGNN predicted “reactivity” or
similar, we could use that (if high reactivity, then the PFAS might degrade given a
catalyst, etc.).
6. Output Aggregation: Prepare a results structure that includes:
▪ MGNN predicted properties (e.g., “Predicted adsorption coefficient: X, toxicity: Y, etc.”).
▪ If any immediate simulation observation (maybe the short MD computed a diffusion
rate or solubility from how it moved, but probably too short to quantify those).
▪ LSTM predicted trend: possibly summarize as “PFAS remains stable over time” or “PFAS
shows signs of slow breakdown over extended time (predicted trend in energy or
structure).” We have to be careful here: without actual chemical reactions, any
"degradation pathway" is hypothetical. Perhaps our LSTM could identify a likely
conformational change pathway (like from one shape to another). We'll phrase output
as such.
▪ If we had multiple PFAS in one simulation, we could predict relative behavior, but we
focus on one at a time.
